# Cursor & Hermes AI services

Начните с `bb cursor-hermes-ai status --json` и `bb plugin config cursor-hermes-ai`.
Полная настройка и ограничения: [README](../../README.md).

Машины задаются ID из `bb machine list --json`. Пустое значение означает основную
машину BB. Авторизация принадлежит нативному CLI на выбранной машине. Для Cursor
используйте согласованный HTTPS_PROXY. Ключи и токены в настройки не копируются.

Для каждого настроенного сервиса выполните последовательно:

```sh
bb cursor-hermes-ai test --service cursor --task thread-title --json
bb cursor-hermes-ai test --service cursor --task commit-message --json
```

Для Hermes замените `cursor` на `hermes`. Успех — `ok: true` и непустой текст в
обоих ответах. Подготовка сессии выполняется до измеряемой генерации. Генерация
ограничена 4,6 секунды при общем лимите BB 5 секунд. Команда `test` пересоздаёт
служебный процесс; запускайте её, когда сервис свободен. При отсутствии входа
потребуется `cursor-agent login` или `hermes login` на выбранной машине.

После обновления BB проверьте SDK, сборку и реальные ответы по разделу README.
Сохраняйте выбор задач AI services, если пользователь не просил его менять.
Результат проверки — готовность сервисов, полученные тексты, длительности и
оставшиеся ограничения. Логи: `bb plugin logs cursor-hermes-ai -n 20`.
